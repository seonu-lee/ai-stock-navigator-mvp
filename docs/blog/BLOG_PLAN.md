# 기술블로그 작성 계획

ai-stock-navigator-mvp 프로젝트 진행 과정을 단계별로 기록한다.
Velog 메인 발행 + GitHub Pages 문서화 병행.

## 전체 블로그 구성 (총 7편)

| 편 | 제목 | 작성 시점 | 대응 개발 단계 |
|----|------|-----------|----------------|

| 2편 | 환경 구축과 API 첫 연동 — 삽질 기록 | 1주차 완료 후 | 환경 세팅 + API 테스트 |
| 3편 | 한국 주식 데이터 수집기 만들기 — pykrx와 크롤링 | 2주차 완료 후 | 데이터 수집 파이프라인 |
| 4편 | 기술적 지표와 이상치 탐지 — 분석 모델링 설계기 | 3주차 완료 후 | 분석 모델링 |
| 5편 | AI 설명 레이어 구축 — 숫자를 말로 바꾸는 방법 | 4주차 완료 후 | AI 설명 레이어 |

## 편별 세부 내용 계획

### 1편 — 프로젝트 기획과 설계

```
- 프로젝트를 시작하게 된 배경
- 초보 투자자가 겪는 진입 장벽 분석
- MVP 범위를 어떻게 결정했는가
- 전체 파이프라인 설계 과정
- 파일구조 설계 이유
```

### 2편 — 환경 구축과 API 첫 연동

```
- Python 3.13 + venv 세팅 과정
- GitHub 레포 초기화
- Gemini/Claude API 키 발급 및 첫 호출
- 더미 데이터로 프롬프트 테스트한 결과
- 겪은 에러와 해결 과정 (삽질 기록)
```

### 3편 — 한국 주식 데이터 수집기 만들기

```
- pykrx란 무엇인가, 왜 선택했는가
- OHLCV 데이터 수집 구조 설명
- 외국인·기관 순매수 데이터 수집
- 네이버 금융 뉴스 크롤링 설계
- SQLite 테이블 설계 과정
- 배치 처리로 전환한 이유
```

### 4편 — 기술적 지표와 이상치 탐지

```
- 이동평균(5·20·60일)이란 무엇인가
- RSI 계산 원리와 과열·과매도 기준
- 볼린저밴드 해석 방법
- Z-score 기반 거래량 이상치 탐지 설계
- KR-FinBERT로 뉴스 감성 점수 산출
- 피어슨 상관계수 기반 섹터 네트워크 구성
```

### 5편 — AI 설명 레이어 구축

```
- 왜 LLM이 수치를 직접 생성하면 안 되는가 (환각 리스크)
- 분석값을 프롬프트로 변환하는 설계 원칙
- 초보자 눈높이 자연어 출력을 위한 프롬프트 엔지니어링
- Gemini API 무료 티어 한계와 배치 처리 전략
- 면책 고지 자동 삽입 구현
- 출력 검증 로직 설계
```

### 6편 — Streamlit으로 대시보드 만들기

```
- Streamlit을 선택한 이유
- 멀티페이지 구성 설계
- plotly 차트 컴포넌트 구현
- 시장 브리핑 / 종목 분석 / Q&A 페이지 구현 과정
- UI에서 면책 고지를 어떻게 자연스럽게 녹였는가
```

### 7편 — MVP 완성 회고

```
- 6주간 개발하며 배운 것
- 잘 된 것과 아쉬운 것
- AI 환각 리스크를 실제로 어떻게 다뤘는가
- MVP 검증 결과 (설명 가독성, 파이프라인 안정성 등)
- 다음 단계(2단계) 개인화 추천으로의 확장 계획
```

## Velog vs GitHub Pages 역할 분담

| 내용 | Velog | GitHub Pages |
|------|-------|-------------|
| 단계별 회고 및 삽질 기록 | 메인 발행 | 링크 연결 |
| 기술 개념 설명 (RSI, Z-score 등) | 메인 발행 | 링크 연결 |
| 프로젝트 전체 문서 | 링크 연결 | 메인 관리 |
| API 설계 문서 | - | 메인 관리 |
| 포트폴리오 페이지 | - | 메인 관리 |

---

## 작성 원칙

- 각 편은 해당 개발 단계 완료 직후 작성한다
- 코드 스니펫은 핵심 부분만 발췌하여 포함한다
- 에러와 해결 과정을 반드시 포함한다 (삽질 기록이 가장 가치 있다)
- 개념 설명은 초보자도 이해할 수 있는 수준으로 작성한다
- 각 편 말미에 다음 편 예고를 포함한다
